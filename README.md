## Testing Approach

My approach starts with understanding the product, the business logic behind it and where failures are most likely to have a meaningful impact.

I focus on:

- Risk-based testing and prioritization
- Requirements and business logic analysis
- Critical user journeys
- Positive, negative and edge-case scenarios
- Behavior beyond the expected happy path
- Technical validation when deeper investigation is required
- Clear evidence collection
- Actionable defect reporting
- Adapting the level of documentation to the project and its risks

The objective is not only to confirm that a feature works, but to understand how it can fail and what that failure means for the user, the business, or the system.

## QA Process

I adapt the QA process according to the product, available documentation, project maturity, risk level and delivery constraints.

For faster or investigation driven work, I may follow a lightweight workflow such as:

**Scope → Risks → Critical Flows → Validation → Evidence → Defects → Retest**

For projects requiring stronger formal traceability, the process can expand to:

**Requirements → User Stories → Acceptance Criteria → Test Conditions → Test Cases → Execution → Defects → Regression → Traceability**

Depending on the project, activities may include:

- Requirements analysis and validation
- User story and acceptance criteria review
- Scope and risk identification
- Test planning
- Test condition and scenario design
- Test case creation and organization
- Test data preparation
- Exploratory testing
- Test execution and reporting
- Defect lifecycle management
- Retesting and regression validation
- Evidence collection
- Traceability management
- QA retrospectives and process improvement
